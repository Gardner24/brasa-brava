feat: scaffold initial system — Phase 0 → Phase 2 frontend with branding

Sets up the full Brasa Brava monorepo end-to-end: discovery, schema,
backend API with full CRUD on products and recipes, recursive cost
calculation, audit trail, frontend dashboard and visual identity.

# Phase 0 — Discovery & ADRs
- Reverse-engineered Plantilla Mauricio final.xlsm (83 ingredients,
  37 recipes, 14 categories with semantic duplicates)
- ADR-001: collapsed 14 → 9 canonical product categories with explicit
  per-product overrides and 1 sub-recipe promotion (Pepinillos)
- ADR-002 to 007: stack (Fastify+Prisma+React+Tailwind), JWT auth,
  multi-tenant via Postgres RLS, bilingual ES/EN with live switch,
  flexible audit modes (FULL/CATEGORY/SPOT/ABC_CYCLE/CUSTOM),
  current-cost only migration (history grows from day 1)

# Phase 1 — Foundation
- pnpm monorepo: apps/{api,web} + packages/{db,shared-types,config}
- docker-compose: Postgres 16 + Redis 7 + MailHog with healthchecks
- Prisma schema: 27 models/enums covering tenants, roles, products,
  categories, recipes, lines, menus, warehouses, stock movements,
  audits, audit counts, stock adjustments, service events, audit_log,
  low stock alerts
- RLS migration: forced row-level security on 17 tenant-scoped tables
  (direct tenant_id and join-based policies), plus generated columns
  (unit_cost, variance_qty, variance_value), CHECK constraints,
  audit_log immutability via revoked grants + defensive trigger
- Reproducible seed: reads .xlsm with exceljs, applies category map
  with quarantine for 16 cost-missing items, promotes sub-recipes,
  signs migration-report-<ISO>.json
- Fastify API: helmet, cors, cookie, rate limit, swagger; plugins for
  JWT auth (Argon2id, refresh rotation with reuse detection),
  tenant context (SET LOCAL within transaction), error handler
  translating Zod/Prisma/DomainError to stable codes, audit log helper
- React + Vite + Tailwind shell with i18next (live ES/EN switch,
  preserves form state via React Hook Form), TanStack Query
- CI: lint, typecheck, unit tests, integration tests against real
  Postgres service, build, pnpm audit, CodeQL weekly

# Phase 2 — Catalog + Recipes
- Schema additions: product_aliases (resolves Paprika Dulce/Ahumada
  inconsistencies), version columns on Product/Recipe for optimistic
  concurrency
- Products CRUD: list with filters (search, category, isActive,
  dataQualityIssue, alias search), detail with price history + uses,
  create, patch with version check, archive (soft delete with
  dependency check), aliases CRUD, paginated price history
- Recipes CRUD: list, detail with **recursive CTE for cost rollup**
  (expands sub-recipes, scales by yield_qty, depth ≤10 safety),
  scale endpoint (cost for N guests with expanded ingredients),
  atomic line replacement with cycle detection on sub-recipes
- Categories CRUD with parent hierarchy, dependency-checked delete
- Audit log endpoint: filterable timeline (entity, entityId, actor,
  action, date range)
- Audit helper: every mutation records before/after/diff to audit_log
- Frontend: react-router-dom v6 routing, AuthContext with auto-refresh
  60s before expiry, ApiError typed client, TanStack Query hooks per
  resource. Pages: LoginPage, CatalogPage (table + 4 filters + status
  badges), RecipesPage (split-pane with live cost from CTE),
  AuditLogPage (timeline + JSON diff details). Sidebar with active
  state, Topbar with logout
